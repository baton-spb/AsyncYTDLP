# Производительность и оптимизация

Библиотека `async-yt-dlp` спроектирована с акцентом на околонулевой оверхед над синхронным `yt-dlp`.

---

## 1. Результаты бенчмарков

- **Оверхед моста прогресса (`ProgressBridge`)**:
  Обработка и передача 10 000 событий прогресса через асинхронную очередь занимает **менее 0.1 секунды**, что составляет микросекунды на один вызов хука.
- **Оверхед диспетчеризации задач (`DownloadManager`)**:
  Диспетчеризация 100 одновременных задач через семафор параллельности занимает **менее 0.05 секунды**.

---

## 2. Советы по оптимизации производительности

### 1. Используйте `extract_flat=True` для плейлистов
Если вам нужен только список ссылок или названий в плейлисте, используйте `extract_flat=True`:
```python
options = YTDLPOptions(extract_flat=True)
info = await ytdlp.extract_info(playlist_url, options=options)
```
Это ускоряет операцию в десятки раз, так как yt-dlp не будет запрашивать отдельные веб-страницы для каждого видео в плейлисте.

### 2. Настраивайте `throttle_interval` для UI и ботов
В Telegram-ботах и веб-интерфейсах слишком частые обновления вызывают превышение лимитов API.
Устанавливайте `throttle_interval`:
- Для Telegram: `1.0` – `2.0` сек.
- Для Web/SSE: `0.3` – `0.5` сек.
- Для консольных утилит: `0.1` – `0.2` сек.

### 3. Ограничивайте качество скачивания
Для ботов и мобильных клиентов часто достаточно разрешения 720p:
```python
options = YTDLPOptions(format="bestvideo[height<=720]+bestaudio/best[height<=720]")
```
Это снижает объем передаваемого трафика и сокращает время работы `ffmpeg`.

### 4. Параллельная загрузка фрагментов (`concurrent_fragments`)
Для HLS и DASH стримов можно включить скачивание фрагментов в несколько потоков:
```python
options = YTDLPOptions(concurrent_fragments=4)
```
