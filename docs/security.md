# Безопасность и защита данных в async-yt-dlp

При работе с внешними медиа-ресурсами и пользовательским вводом безопасность
имеет первостепенное значение.

В библиотеке `async-yt-dlp` реализован комплекс защитных мер на всех уровнях.

---

## 1. Автоматическая санитизация секретов при логировании

В параметрах `YTDLPOptions` могут передаваться конфиденциальные данные:
- Пароли учетных записей (`password`, `videopassword`)
- Токены авторизации и API-ключи
- Учетные данные прокси (`http://user:password@proxy`)
- Заголовки HTTP (`Authorization: Bearer ...`, `Cookie`)

Методы `to_safe_dict()`, адаптер логирования `YTDLPLoggerAdapter` и функции `redact_options` / `redact_url`
**автоматически маскируют** все конфиденциальные поля значением `********`, исключая их попадание в логи,
консоль или Sentry.

---

## 2. Защита от SSRF и протокола `file://`

По умолчанию загрузка файлов по локальной схеме `file:///` **заблокирована** валидатором:

```python
# Попытка передать локальный путь вызовет ValidationError
await ytdlp.download("file:///etc/passwd")  # ValidationError: Схема 'file://' отключена по умолчанию
```

Если вашему доверенному приложению действительно требуется локальная обработка файлов, включите флаг явно:
```python
options = YTDLPOptions(allow_file_urls=True)
```

---

## 3. Санитизация путей и имен файлов

- Библиотека проверяет входные пути на отсутствие опасных `null-байтов` (`\x00`).
- Поддерживаются флаги `restrict_filenames=True` (только безопасные ASCII-символы) и `windows_filenames=True` (запрет зарезервированных имен устройств Windows `CON`, `PRN`, `AUX`, `NUL` и недопустимых символов `*?:"<>|`).

---

## 4. Изоляция процессов и потоков

- Синхронное ядро `yt-dlp` выполняется в изолированных потоках.
- Для каждого запроса создается независимый экземпляр `YoutubeDL`, что исключает утечку состояния сессий и cookies между разными пользователями.
